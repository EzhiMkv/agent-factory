# agent-factory

> Завод агентской разработки: тикеты из спеков → параллельные CLI-агенты →
> judge-проверка → мерж. Продуктовый полигон конвейера — **web3-игра
> «Пухляндия»**: милые существа, живущие в блокчейне.

**Статус: полигон №1 (коррелятор новостей/цен, спеки 001–002) отработан
конвейером и удалён — остался в истории git как референс. Полигон №2 —
игра, скелет с нуля. Отправная точка — [TZ.md](TZ.md) (продукт) и раздел
«Конвейер» ниже.**

## Зачем этот проект

Продукт здесь — не цель, а полигон. Цель — показать и отработать
**производственный сетап агентской разработки**: как инженер декомпозирует
спеку на короткие проверяемые тикеты, раздаёт их параллельным CLI-агентам
(Claude Code / Codex / opencode), и как результат проверяется тестами и
judge-моделью до мержа.

## Два слоя

### Слой 1 — продукт (полигон): web3-игра «Пухляндия»

MVP, декомпозиция и границы — [TZ.md](TZ.md). Суть в одну фразу демо:

> Существо живёт в блокчейне: его ДНК, каждая забота и эволюции —
> транзакции, а арт рисуется контрактом на лету. И вся игра разработана
> агентами из спеков.

Ключевые решения продукта (обсуждение зафиксировано в TZ.md):

- **Сеть — Base Sepolia (демо-основа):** продукт завязан на частые
  автономные вызовы питомца-агента, L1 отпадает по газу/блоктайму.
  Base — дешёвый газ, ERC-6551, строчка «Base / EVM / ERC-6551» в
  резюме. Anvil — только юнит-тесты Foundry.
- **ERC-6551 Token Bound Account у питомца:** у каждого пухлика свой
  кошелёк (адрес/баланс/ачивки видны в UI) — фундамент для автономного
  AI-агента в v2.
- **Burner-кошелёк за кадром** (никакого MetaMask-фрикциона для
  смотрящего), он-чейн ДНК + генеративный SVG-арт прямо в контракте
- **Без торговой экономики и токенов в MVP**
- Доктрина «окситоцин и няшность» для всего UI/копирайта/арта —
  обязательна (см. AGENTS.md)

### Слой 2 — конвейер

Планируемая структура репозитория:

```
├── AGENTS.md            # правила для агентов — единый вход для CI-агентов
├── openspec/            # спеки: proposal → spec-delta → tasks.md
│   └── changes/<фича>/  #   фича = набор мелких верифицируемых тикетов
├── orchestrator/        # очередь тикетов + диспетчер по параллельным агентам
├── worktrees/           # git worktree на агента (изоляция параллельных прогонов)
├── judge/               # gate перед мержем: judge-LLM ревьюит дифф против спеки
├── dashboard/           # метрики конвейера: тикетов/день, first-pass yield
├── packages/            # слой 1: игра (contracts + web)
└── docs/                # TZ, журнал прогонов, lessons learned
```

Как это читается на язык задач:

| Слово | Что у нас |
|---|---|
| specs | `openspec/changes/*/proposal.md` + `tasks.md`: тикет = короткая проверяемая задача |
| loops | прогон тикета агентом: план → код → тест → повтор по логам падения → сдача |
| оркестрация | `orchestrator/`: очередь тикетов, 3–5 агентов в worktrees, мерж по готовности |
| прогон задачи | лог одной задачи от спеки до мержа: что агент спросил, что judge отклонил, что правилось руками |
| judge перед мержем | `judge/`: модель-судья другого вендора ревьюит дифф против спеки; verdict — комментарий в PR |

Метрики конвейера ценны не менее продукта: тикетов/день, доля first-pass
через judge, стоимость тикета, ночные прогоны в истории.

## Что делать следующей сессии

Цель сессии — полный живой цикл конвейера на реальных тикетах игры, чтобы
репетицию демо можно было вести по чек-листу.

1. **Скелет полигона**: `packages/contracts` (forge init, `forge test`
   зелёный; foundry — в `~/.foundry/bin`) + `packages/web` (Vite/React,
   сцена-заглушка «встреча с пухликом»), pnpm workspace.
2. **Спека** `openspec/changes/003-critter-core/` по «Декомпозиции MVP»
   из TZ.md: 8–10 крошечных тикетов; один микро-тикет (~15 мин работы
   агента) пометить меткой «hot» — он пойдёт в живой прогон на демо.
3. **Оживить judge**: судья — другой вендор, не основной кодящий агент.
   Доступ можно взять из `~/projects/lfstl/doc2crm/.env`
   (LLM_PROVIDER/LLM_API_KEY → `JUDGE_*`, см. `.env.example`) или завести
   ключ OpenRouter. Прогнать дважды: на честном диффе → approve, на
   намеренно мутном диффе → request-changes (оба отчёта в
   `judge/results/` — доказательство, что gate не фикция).
4. **Полный цикл на 2–3 тикетах параллельно**: claim → worktree → агент
   → коммит → judge → мерж → записи в `docs/runs/`. Портфолио-штрих:
   минимум один request-changes с добором — чтобы было видно, что gate
   реально заворачивал работу.
5. **Метрики**: `node orchestrator/index.mjs snapshot` после каждого
   мержа; вывести на `dashboard/`.
6. **Репетиция**: прогнать демо по чек-листу с таймером, 30 мин.

## Принципы

- Конвейер важнее продукта. Фича игры ценна в первую очередь тем, что
  даёт пачку тикетов для конвейера.
- каждый тикет — короткий и проверяемый: код + тест (Foundry для
  контрактов, vitest для TS), а не «сделай модуль».
- Няшность — функциональное требование продукта, а не вкусовщина:
  judge отклоняет «скучный» UI как регрессию (доктрина в AGENTS.md).
- Никакого вайб-кода руками поверх агентов: ручной фоллэк отдельно и явно.
- Все секреты — в `.env` (`.env.example` обязателен), в репо не попадают.
