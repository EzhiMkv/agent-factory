# dashboard

Дашборд конвейера для живого показа: очередь тикетов, вердикты судьи,
журнал прогонов, адреса живого деплоя.

Два режима:

```bash
pnpm dashboard          # пересобрать статичный срез → dashboard/index.html
pnpm dashboard:live     # живой сервер → http://localhost:4173
```

- **Статичный** (`index.html`): самодостаточная страница с последним срезом,
  открывается офлайн двойным кликом — когда сеть/сервер не нужны.
- **Живой** (сервер на 4173): страница раз в 4 секунды опрашивает
  `/api/data`, сервер каждый раз собирает свежий срез — закрыли тикет,
  судья вынес вердикт, агент дописал лог → дашборд обновляется сам,
  без перезагрузки. Порт меняется через `PORT=5000 node dashboard/serve.mjs`.
- **Пульт**: карточки канбана перетаскиваются — «Готово» закрывает тикет
  (галочка в `tasks.md`), «Следующая»/«Очередь» переставляют секцию тикета
  в спеке (порядок очереди), «В работе» делает настоящий claim у
  orchestrator'а (ветка `work/<change>/<section>` + worktree). Кнопки
  остаются как дублёры: «закрыть / переоткрыть» и «судье» — запуск judge
  по ветке тикета прямо с экрана (секреты судьи сервер читает из корневого
  `.env`, в браузер они не попадают; вердикт прилетает в ленту сам, пока на
  карточке мигает «судья думает…»). При 100% появляется праздничный баннер.
  В офлайн-режиме (файл открыт без сервера) кнопки скрыты, перетаскивание
  выключено.

Источники данных: orchestrator (очередь тикетов), `judge/results/`
(вердикты), `docs/runs/` (журнал прогонов), фиксированный список адресов
живого деплоя внутри `build.mjs`. Сборка дублирует срез в машиночитаемый
`metrics/<дата>-snapshot.json`.
