# Прогон 2026-10-21 — 003-tc-10 web burner-кошелёк + Base Sepolia

- Спека: `openspec/changes/003-critter-core/tasks.md#tc-10`
- Агент: opencode / glm-5.3-flash-free, ветка `work/003-critter-core/tc-10`
- Постановка: burner-кошелёк из `VITE_DEMO_KEY` + клиент Base Sepolia через
  `VITE_RPC_URL`; кнопки заботы шлют транзакции; таймаут сети → милый тост
  «Сеть притихла — попробуем ещё разочек?».

## Что сделано
- `wallet.ts`: lazy-синглтон `getCareClients()` — приватный ключ валидируется
  по форме `0x + 64 hex`, иначе `null` (нет крика, забота остаётся локальной);
  публичный `createPublicClient` + `createWalletClient` на `baseSepolia`.
  `critterAddress()` теперь живёт здесь (CritterView импортирует).
- `care.ts`: `sendCare(feed/play/sleep)` → `writeContract` адреса
  `VITE_CRITTER_ADDRESS` с «кусочком заботы» = 20; `Promise.race` с таймаутом
  30с → результат `{ kind: "quiet" }` вместо исключения; без ключа/адреса —
  `{ kind: "skipped" }` (сцена не падает до деплоя).
- UI-проводка: кнопки App идут через `deliverCare` → тосты `SENT_NOTE` /
  `QUIET_NOTE`; у Toast добавлен тон `quiet` (персиковый) и `note()`;
  CritterView получил busy-состояние («Пыхтим… несем заботу в сеть» +
  мягкий pulse-анимация, reduced-motion учтён).
- `.env.example`/`env.d.ts`: `VITE_DEMO_KEY` задокументирован, реальных
  значений нет — только тестнетовый burner.

## Итерации и проблемы
- `tsc` выдал две строгие ошибки viem: `ReturnType<typeof createWalletClient>`
  не валидируем структурно (широкая union-типизация tx) → типы клиентов
  берутся прямым инференсом `ReturnType<typeof buildClients>`. Вторую ошибку
  сняло «не передаём chain в writeContract» (клиент уже привязан к chain).
- Дифф тикета превысил бы ~300 строк одним коммитом (≈320+), поэтому сдан
  двумя коммитами: логика+моки (222 строки) и UI-проводка (~120) —
  разложение ради ревью, а не два тикета.
