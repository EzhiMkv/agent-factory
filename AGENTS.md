# AGENTS.md — правила работы агентов в этом репозитории

> Читай это ДО любого изменения кода. Суть: ты агент конвейера, твой тикет
> специфицирован в openspec, путь к сдаче — короткая ветка + тесты + дифф,
> который проверит человек и judge-модель.

## Контекст: что продаём (важно понять с первой минуты)

Продаём не игру и не «просто код» — **живой сетап агентской разработки**.
Суть, ради которой всё затевалось:

> Сетап агентской разработки, который видно вживую: specs, loops,
> оркестрация, прогон задачи.

Поэтому ценность любой сессии измеряется тем, что можно показать живьём:

- спека разложена на тикеты: очередь — `openspec/changes/*/tasks.md`,
  сбор — `node orchestrator/index.mjs list/board/snapshot`;
- тикет уходит агенту: claim → worktree → ветка `work/<NNN>/<slug>`;
- агент делает по правилам ниже и сдаёт коммит(ы) с зелёными тестами;
- judge **реально** ревьюит дифф: вердикт approve / request-changes
  пишется в `judge/results/*.md` — заполненных вердиктов в репо должно
  быть много (включая примеры request-changes с добором);
- «прогон задачи» фиксируется в `docs/runs/<дата>-<тикер>.md` по шаблону
  `docs/runs/TEMPLATE.md` — тот самый лог, который сторонний человек прочитает глазами;
- игра ценна ровно настолько, насколько даёт понятные тикеты и милую
  30-секундную сцену. Не углубляйся в гейм-дизайн, пока конвейер не
  отработал полный цикл на паре тикетов.

## Продукт: web3-игра «Пухляндия» (полигон конвейера)

- Игра про милых существ: вылупиться из яйца → заботиться (корм/игра/сон)
  → расти и эволюционировать. ДНК и эволюции — он-чейн, арт существа
  рисуется контрактом (SVG в tokenURI).
- **Продаётся АГЕНТНАЯ РАЗРАБОТКА**, не конечный продукт: спеки →
  тикеты → параллельные агенты → judge. Игра — полигон, выбранный за
  мгновенную наглядность.
- **Критерий любого продуктового тикета:** прирост к 30-секундной демо-сцене
  (см. TZ.md). Минимум трения: burner-кошелёк за кадром, демо-сеть —
  **Base Sepolia** (бечёвка: cheap gas, ERC-6551, basescan-лента), anvil
  — только юнит-тесты Foundry.
- **Секреты:** приватные ключи/RPC — только в `.env` (шаблон
  `.env.example`). В коде и тестах никаких ключей: Foundry-тесты живут
  на стандартных anvil-аккаунтах; деплой-ключ демо-аккаунта — только
  тестнетовый, без реальных средств.

### Доктрина «окситоцин и няшность» — обязательна

Весь UX-слой, копирайт, арт и даже экраны ошибок заряжаются на милоту:

1. Мягкие скруглённые формы («желе»), пастельная палитра, никакого
   корпоративного холода. Крупные глаза с бликами — главный эмо-носитель.
2. Живое поведение обязательное: idle-мигание, зевание, толкание глаз за
   курсором, реакция на прикорм/игру/сон — существо всегда кажется живым.
3. Копирайт заботливый и ласковый («Ням-ням!», «Пухлик доволен»). Никаких
   сарказма, чернухи и банковского тона. Ошибки тоже милые: «Пухлик
   зазевался — попробуем ещё разочек?».
4. Жёсткое «работает, но скучно» = регрессия продукта: judge имеет
   право возвращать такие диффы.

## Словарь проекта

- **Спека** — `openspec/changes/<NNN-название>/`: `proposal.md` (зачем),
  `spec-delta.md` (какие требования добавляются), `tasks.md` (чеклист тикетов)
- **Тикет** — один пункт tasks.md с id вида `003-tc-01`: короткая задача,
  которую проверяет запуск одного теста/сборки
- **Контракт-слой** — Solidity-пакеты (`packages/contracts`): существо,
  ДНК, уход, эволюция, SVG-рендер; тесты Foundry
- **Клиент-слой** — `packages/web`: Vite + React + TS strict, wagmi/viem,
  анимации сцены существа

## Что тикет обязан соблюдать

1. Один логический шаг. Если дифф превышает ~300 строк — стоп, отчитайся
   и предложи декомпозицию, не продолжай.
2. Новая логика — только с тестом рядом: контракты — Foundry (`forge test`),
   TS — `*.test.ts` (vitest). Тест без логики и логика без теста не идут
   в коммит.
3. TypeScript `strict`. Никаких `any` без комментария-обоснования.
4. Секреты не попадают в код: конфигурация через `.env` (`.env.example`
   обязателен), ключи читаются в одном месте пакета.
5. Не трогай поведение независимых частей вне назначенного тебе тикета:
   деплой-скрипты, генератор ДНК и рендер SVG меняются только своим тикетом.
6. Не повышай версии зависимостей и не добавляй новых без указания в тикете.

## Цикл работы над тикетом (loop)

1. Прочитай спеку целиком и батч своего тикета; запиши план в начале
   сессии (план тикета).
2. Работай в отдельной ветке: `work/<NNN>/<slug>` от актуального `main`.
3. Ревью своего диффа перед сдачей: `git diff main` глазами — гонять ли
   лишние файлы? Заглушенные тесты? Дебаг-выводы? Анти-няша в UI?
4. Сдача: коммит(ы) с сообщением `(<NNN-tc-XX>) <что сделано>`, тесты
   зелёные локально: `forge test` (контракты) + `pnpm -r test` (TS).
5. Если тесты упали — чини, не оставляй красным; после 3 неудачных
   попыток — стоп и отчёт (что блокирует, почему застрял, что пробовал).

## Judge-gate

Дифф каждого тикета перед мержем смотрит модель-судья другого вендора
с промптом из `judge/prompt.md`: соответствие спеке, отсутствие галлюцинаций
API, покрытие тестами. Verdict: approve / request-changes — второе возвращает
тикет в работу. Для UI-диффов judge дополнительно проверяет доктрину
нятости: скучный/агрессивный/корпоративный UI = request-changes.
Не пытайся «договориться» с судьёй: исправляй суть замечаний.

## Операционное

- Параллельная работа агентов — через git worktrees (см. `orchestrator/README.md`);
  не работай в чужой ветке
- Логи прогонов агента сохраняй в `docs/runs/<дата>-<тикет>.md` по шаблону
  `docs/runs/TEMPLATE.md` — «прогон задачи» для демо строится из них
- Команды: `forge build`, `forge test` (packages/contracts); `pnpm -r
  build/test/lint` (packages/web). Foundry живёт в `~/.foundry/bin` —
  если `forge` не в PATH: `export PATH="$HOME/.foundry/bin:$PATH"`
- Judge-прогон: `node judge/index.mjs --branch work/<NNN>/<slug>`
  (конфиг `JUDGE_*` в `.env`, см. `.env.example`; судья — **другой
  вендор**, не вендор кодящего агента); отчёт ложится в `judge/results/`
- Метрики: `node orchestrator/index.mjs snapshot` после мержа/закрытия
- Критерий «тикет закрыт»: тесты зелёные + judge approve + запись в
  `docs/runs/` + отметка `[x]` в `tasks.md` спеки. Пропустил step —
  тикет не закрыт
- Всё, что нужно человеку перед мержем, — шли в PR-описание кратко:
  что, почему, как проверил
